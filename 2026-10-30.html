1. Cursor 마켓플레이스의 Claude Code 확장에서 SSH 백도어가 발견되었다

출처: Phorion · Cursor 보안 공지 · The Register (10-30)

Phorion은 Cursor 마켓플레이스의 Claude Code for VS Code 확장 2.1.313에서 백도어를 찾았다. Cursor는 2.1.312와 2.1.313이 악성이라고 공지했다. 배포 시간은 10-29 09:27–20:35 UTC(10-29 18:27–10-30 05:35 KST)이다. 코드는 사용자 조작 없이 바로 실행된다. 공격자 SSH 키를 authorized_keys에 넣고, 역방향 SSH 터널과 지속 실행을 설치한다. 호스트 이름, 사용자 이름, Git 이메일, 공인 IP도 보낸다. 대부분의 macOS·Windows에서는 관리자 권한이 없어서 SSH 켜기 단계가 실패했다. Sophos와 The Register는 최대 5,000명이 영향을 받았다고 쓴다. Anthropic 직원은 HN에서 "Anthropic 시스템 침해가 아니다"라고 썼다. 공식 VS Code 마켓플레이스와 OpenVSX는 영향이 없다고 했다. Anthropic은 다음 버전을 2.1.314로 냈다.

왜 중요한가. 코딩 에이전트 확장은 IDE와 같은 권한으로 소스 코드와 키에 접근한다. 확장을 지워도 지속 실행 스크립트는 남는다. 해당 기간에 Cursor로 이 확장을 받았다면 svc-telemetry 키를 찾고 자격 증명을 바꾸어야 한다.

2. Microsoft Mage-VL-Cowork: GUI와 터미널을 함께 쓰는 4B 컴퓨터 사용 에이전트

출처: Hugging Face 모델 카드 · GitHub microsoft/Mage (10-30 21:13 KST 공개)

Mage-VL-Cowork는 4B 비전-언어 모델이다. 한 정책 모델이 화면 클릭(computer_use)과 bash 실행을 함께 고른다. 백본은 Mage-ViT와 Qwen3-4B-Instruct-2507이다. OSWorld-Verified 361개 과제, 50단계 예산에서 66.0%를 받았다(2회 평균). 같은 표에서 ScaleCUA-Qwen3.5-9B는 68.7%, Qwen3.6-27B는 63.9%, OpenCUA-72B는 44.9%이다. GPT-5.4-mini는 69.6%, Claude Opus 4.7은 78.0%, 사람 기준은 72.4%이다. 온라인 RL은 SFT보다 10.16%p를 올렸다. 과제당 출력 토큰은 25.4% 줄었다. 문맥은 32,768 토큰이다(구조상 262,144까지). 라이선스는 Apache-2.0이다. bf16 가중치는 9.48 GB이다. 가격: 출처에 없음. 추론 하드웨어 요구: 출처에 없음(SGLang Docker 실행 예시는 있다).

왜 중요한가. 4B 크기로 72B 오픈 모델보다 높은 OSWorld 점수를 냈다. 로컬 PC 자동화 에이전트로 쓸 수 있는 크기이다. 점수는 모두 Microsoft 자체 평가이다. 판정: 써볼 만함. 크기가 작고 라이선스가 열려 있으며, 평가 재현 코드가 있다.

3. Pika H3 Flex: 오디오가 붙은 영상을 6단계로 만드는 오픈 가중치 모델

출처: Hugging Face 모델 카드 · GitHub Pika-Labs/Pika-H3-Flex (10-30 02:08 KST 공개)

Pika H3 Flex는 MiniMax-H3를 후속 학습한 영상·오디오 생성 모델이다. 가중치는 LoRA 어댑터 2개(FL2VA, Ref2VA)와 MiniMax-H3 기본 구성 요소이다. HF API의 safetensors 합계는 약 331억 파라미터이다. 6번의 샘플링 단계로 영상과 32 kHz 스테레오 오디오를 만든다. 로컬 출력은 480p·768p, 24 fps, 5–15초, 11개 화면비이다. 참조 입력은 최대 12개(이미지 9, 영상 3, 오디오 3)이다. 1080p·2K·4K와 오디오 분리는 유료 Pika API에서만 된다. H100 80GB 한 장에서 시험했다. 기본 구성 요소는 약 210 GB이다. 라이선스는 MiniMax H3 Community License이다. 벤치마크 점수: 출처에 없음.

왜 중요한가. 오디오가 붙은 영상 모델을 적은 단계로 로컬에서 돌릴 수 있다. 그러나 H100급 GPU가 필요하고 고해상도는 API로만 열었다. 판정: 지켜볼 만함. 하드웨어 요구가 크고 품질 비교 수치가 없다.

반응. HF 좋아요 194, 다운로드 87. GitHub 별 215, 포크 11. HN 글은 찾지 못했다.

5. Herdr 데스크톱 앱: 터미널과 코딩 에이전트를 한 창에서 관리

출처: GitHub herdrdev/herdr-app (10-30)

Herdr는 터미널과 코딩 에이전트를 위한 데스크톱 앱이다. 작업을 space, tab, pane으로 나눈다. 에이전트 사이드바는 각 에이전트 상태를 Working, Blocked, Done, Idle로 보여 준다. 다른 에이전트가 시작한 작업자도 목록에 나온다. 창을 닫아도 터미널은 계속 돈다. Linux(x86-64, ARM64), Apple Silicon macOS, Windows를 지원한다. Linux는 Vulkan 드라이버가 필요하다.

왜 중요한가. 여러 코딩 에이전트를 동시에 돌릴 때 어느 에이전트가 사용자를 기다리는지 한눈에 본다. tmux와 일반 터미널에는 이 상태 표시가 없다. 판정: 써볼 만함. Apache-2.0이고 개발이 활발하다. 단, 설치 스크립트는 먼저 읽어 보아야 한다.

반응. HN 346점 / 댓글 235. GitHub 별 890, 포크 77, Apache-2.0, 10-16 생성, 마지막 push 10-30.

6. tinyworldformer: Raspberry Pi Pico 2 W에서 도는 초소형 월드 모델 (함께 본 실험: doomformer)

출처: GitHub · HN (10-30)

tinyworldformer는 신경망 2개를 Pico 2 W(RP2350)에서 돌린다. 월드 모델은 현재 화면과 행동으로 다음 화면과 보상을 예측한다. 이 모델은 루프 트랜스포머이고 int8로 양자화했다. 크기는 26k–131k 파라미터이다. 행동 모델은 9k–16k 파라미터 MLP이다. 둘 다 실제 게임 없이 서로의 출력만 쓴다. 같은 날 doomformer도 나왔다. doomformer는 정수 신경망을 DOOM 맵으로 컴파일한다. MNIST 시험 숫자 10,000개를 모두 NumPy와 똑같이 계산했다.

왜 중요한가. 월드 모델이 마이크로컨트롤러에서도 돈다는 작은 증명이다. 실용 도구는 아니다. 판정: 지켜볼 만함. 교육과 실험용이다.

8. SkyPilot: Grace Blackwell NVL72 랙에서 쓸 수 있는 GPU를 27% 늘리는 스케줄링

출처: SkyPilot 블로그 (10-29 게시, HN 10-30)

NVL72는 한 랙의 GPU 72개를 하나의 NVLink로 묶는다. 작업이 랙을 넘으면 InfiniBand를 쓰고 성능이 떨어진다. 같은 학습 작업을 NVLink 대신 InfiniBand로 돌리면 성능이 43% 떨어진다고 SkyPilot은 쓴다. 실제 클러스터의 노드 비가용률은 약 2%였다. 이 조건에서 16노드 단위는 18노드 단위보다 쓸 수 있는 용량이 27% 크다(2,037 대 1,602 노드). SkyPilot은 랙 위치를 아는 배치, 제자리 복구, 자동 조각 모음을 제공한다.

왜 중요한가. 대형 학습·추론 클러스터에서 배치 방식만 바꾸어도 쓸 수 있는 GPU가 늘어난다. 이 글은 SkyPilot 제품 소개도 겸한다.

반응. HN 142점 / 댓글 22.

9. HF 오늘의 논문: IDM, A-RSI, 벤치마크 난이도 분석, LOWN

출처: Hugging Face Daily Papers (10-30)

IDM(추천 237)은 텍스트-이미지 모델을 1–2단계 생성으로 증류하는 방법이다. Z-Image-Turbo 6B와 Qwen-Image 20B에서 시험했다. 2번의 네트워크 계산에서 LongText-Bench 중국어 94.25%, 영어 90.20%를 받았다. A-RSI(추천 150)는 외부 데이터 없이 스스로 과제를 만들어 학습한다. 11개 벤치마크 평균을 57.77에서 61.05로 올렸다. "Your Benchmark Is an Empirical Measure Over Difficulty"(추천 140)는 7개 분야 25개 벤치마크를 난이도 분포로 분석했다. 보완 방법 BenchFill을 제안한다. LOWN(추천 90)은 확산 VLM의 이미지 의존을 분석했다. LLaDA-V에서 이미지를 빼도 결과 토큰이 바뀐 단계는 22.8%뿐이었다(최저 7.9%).

왜 중요한가. 벤치마크 해석과 적은 단계 생성의 효율이 오늘 논문의 중심이다. 리더보드 수치를 볼 때 난이도 편향을 함께 보아야 한다.
