1. Memdoor team-solve: Qwen3.8-27B 다섯 개가 LiveCodeBench Hard에서 Fable 5를 앞섰다

출처: GitHub guregodevo/memdoor · HN

Memdoor는 Go로 만든 단일 바이너리 코딩 에이전트다. team-solve 워크플로는 작은 모델 다섯 역할(계획, 아이디어 2개, 풀이, 관리, 수리)을 쓴다. 각 역할은 새 문맥에서 시작하고 디스크 파일로만 소통한다. 이 방법은 GVS5H 논문(Lee, 2026)을 YAML 8개로 다시 만든 것이다. LiveCodeBench Hard 앞 10문제를 5번씩 풀었다. 평균은 이 워크플로 9.8점, 논문 저자 하네스 9.6점, Fable 5 한 번 호출 8.0점이다. 한 번 실행은 중앙값 40분, $0.39이다. 50번 실행에 $35.79가 들었다. 실행 호스트는 OpenRouter다.

왜 중요한가. 오픈 웨이트 27B 모델 여러 개를 엮으면 상용 최상위 모델 한 번 호출을 넘을 수 있다는 근거다. 저자도 표본이 10문제뿐이라 9.8과 9.6 차이는 잡음 안이라고 밝혔다. 문제가 2025년 봄 대회라서 학습 데이터 오염 가능성도 배제하지 못했다. 판정: 지켜볼 만함. 결과 로그가 모두 공개되어 재현은 쉽다. 하지만 표본이 작다.

반응. HN 418점, 댓글 202개. GitHub 별 221개. 라이선스 Apache-2.0. 마지막 push 2026-11-02 07:15 KST.

3. JEPA로 플라톤 표현 가설을 증명하고 개선했다

출처: arXiv 2610.39302 · Hugging Face Daily Papers · HN

논문은 "플라톤 표현 정리"를 증명했다고 밝힌다. 서로 다른 모달리티에서 따로 학습한 JEPA가 같은 장면의 두 관측을 양성 쌍으로 쓰면 회전 하나만큼만 다른 표현을 배운다는 내용이다. 저자는 다음 토큰 예측이 "나쁜 관측 쌍"을 쓰는 JEPA라고 본다. 같은 말뭉치에서 좋은 관측 쌍은 다음 토큰 예측보다 학습 샘플이 42배 적게 든다. 109M 텍스트 JEPA는 DINOv2·CLIP 이미지 인코더와의 정렬에서 72B까지의 모든 평가 언어 모델을 앞섰다. 쌍 없는 ImageNet-100 top-5에서 64%를 냈다. 8B까지의 언어 모델 최고 기록은 56%였다. COCO 캡션 CIDEr는 .838이다.

왜 중요한가. 규모만 키우는 것보다 학습 쌍 설계가 표현 정렬에 더 중요하다는 주장이다. 작은 인코더로 멀티모달 정렬을 싸게 얻을 길을 보여 준다.
