1. TwIL-8B: Granite 4.2 8B 기반 수학·코드 추론 모델 공개

출처. webAI (Hugging Face 모델 카드, 11-08 18:57 KST 게시)

요약. webAI는 TwIL-8B를 공개했다. 시작 모델은 ibm-granite/granite-4.2-8b이다. 파라미터는 8.79B이다. 문맥은 131,072 토큰이다. 학습은 전체 SFT 다음 GRPO/DAPO 강화학습이다. MATH-500은 98.2이다. Qwen3.5-9B는 96.6, Gemma 4 31B는 87.9이다. LiveCodeBench는 81.6이다(verbose 변형 기준). Gemma 4 31B는 80.0, Qwen3.5-9B는 65.6이다. IFBench는 74.4로 Qwen3.5-9B보다 9.9점 높다. GPQA Diamond는 70.2로 Qwen3.5-9B보다 11.5점 낮다. AIME 2026 문제당 출력 토큰은 약 19.5k이다. Qwen3.5-9B는 31.2k이다. bf16은 16.38 GiB, Q4_K_M GGUF는 4.98 GiB이다. 라이선스는 webAI Non-Commercial License 1.0이다. 상용 사용은 막힌다. API 가격은 출처에 없음.

왜 중요한가. 8B 크기로 수학·코드 점수가 Gemma 4 31B보다 높다. 경쟁 수치는 회사가 다시 측정하지 않은 공개 수치이다. 지식 과제는 약하다. 판정: 지켜볼 만함. 비상업 라이선스라서 업무 사용은 어렵다.

반응. HF 좋아요 231. HN 토론 없음. 링크: 원문 · 기본 모델

2. HyperFlow H3 Flash: MiniMax-H3 영상+음성 모델을 13.7B, 4–8단계로 압축

출처. Video Rebirth (GitHub·Hugging Face, Show HN)

요약. Video Rebirth는 MiniMax-H3의 압축판을 공개했다. 영상과 스테레오 음성을 함께 만든다. 파라미터는 13.7B이다. 샘플링은 4, 6, 8단계이다. CFG를 쓰지 않는다. 5.2초 클립 6단계 생성은 RTX 5090 1장에서 92초이다. H200 1장에서는 36초이다. Q4_K_M GGUF는 9.1 GB이다. 24 GB와 32 GB GPU에서 측정했다. 라이선스는 Apache-2.0이다. 스타는 136개이다. 저장소는 11-06에 만들었다. 품질 벤치마크 수치는 출처에 없음.

왜 중요한가. 소비자 GPU에서 영상과 음성을 함께 만드는 오픈웨이트 선택지이다. 판정: 지켜볼 만함. 첫 실행 내려받기가 약 90 GB이다.

반응. HN 75점·14개. GitHub 스타 136. 링크: 원문 · 가중치 · HN 토론

3. llama-modchip: 284B DeepSeek-V4-Flash를 64GB RAM CPU에서 실행

출처. GitHub (synchopate)

요약. llama-modchip은 llama.cpp용 커널 패치와 양자화 도구 모음이다. DeepSeek-V4-Flash(284.33B, 활성 13.17B)를 1.71 bpw로 줄인다. 파일 크기는 56.56 GiB이다. 기존 UD-IQ1_S는 76.87 GiB이다. 256K 문맥에서 최대 메모리는 57.61 GiB이다. 16코어 Zen 5에서 프리필은 44.36 tok/s이다. 패치 전은 25.0 tok/s이다. 생성 속도는 9.1–14.7 tok/s이다. GPU는 쓰지 않는다. 30B MoE는 25.0–111.6 tok/s이다. 라이선스는 Apache-2.0이다. 스타는 459개이다. 최신 릴리스는 v2.4.0(11-04)이고 마지막 푸시는 11-08이다.

왜 중요한가. GPU 없이 대형 MoE를 돌리는 길을 보여 준다. 수치는 저자 측정이다. 전용 텐서 형식이라 일반 llama.cpp, Ollama, LM Studio는 파일을 읽지 못한다. 판정: 지켜볼 만함.

반응. HN 328점·129개. 링크: 원문 · HN 토론

4. MaxxBench: DeepSWE 과제를 조금 바꾸자 점수 차가 크게 벌어짐

출처. MaxxBench (unlap.ai)

요약. MaxxBench는 DeepSWE 과제 89개의 요구 사항이나 시작 코드를 바꿨다. 정답 패치 증가는 중앙값 17줄(3.5%)이다. Claude Opus 5.5는 74.2%에서 76.4%로 올랐다. GPT-6 Astra는 74.1%에서 71.9%이다. Gemini 3.8 Flash는 73.8%에서 53.4%로 떨어졌다. DeepSeek V4.1 Flash는 74.2%에서 55.6%이다. 15개 설정의 점수 폭은 20.9점에서 48.3점으로 넓어졌다. Opus 5, GLM 5.3, GLM 5.3 Flash 실패의 약 4분의 1은 새 요구를 이해한 뒤 원래 동작으로 되돌린 경우이다.

왜 중요한가. 공개 벤치마크 점수가 비슷해도 요구 변경 대응력은 크게 다르다. 모델을 고를 때 변형 과제 점수를 같이 봐야 한다.

반응. HN 383점·102개. 링크: 원문 · HN 토론

5. Claude Code "Don't ask again" 규칙이 공개 GitHub 파일 1,122개에 비밀번호를 남김

출처. Apiiro 보고서 (11-05 게시, 11-08 갱신). 수치는 The Hacker News·LATENT 기사로 확인

요약. Claude Code에서 "Yes, and don't ask again"을 고르면 명령을 .claude/settings.local.json에 저장한다. 명령에 넣은 비밀번호도 평문으로 저장된다. Apiiro는 공개 GitHub에서 이 파일 104,185개를 모았다. 그중 1,122개(약 1.1%)에 비밀이 있었다. 서로 다른 비밀은 1,379개이다. AWS 키 23개, SSH 로그인 43개가 있었다. LATENT 계산으로 gitleaks와 TruffleHog를 함께 써도 215개 파일(19.2%)을 놓쳤다. Apiiro는 비밀이 아직 유효한지 시험하지 않았다.

왜 중요한가. 에이전트 권한 승인 기록도 비밀 저장소가 된다. 먼저 키를 교체하고 파일을 git 추적에서 빼야 한다. 명령에는 환경 변수를 쓴다.

6. MAPLE: Gemma 4 26B-A4B 전문가 80개를 잘라 6GB GPU에서 45.4 tok/s

출처. GitHub (Show HN)

요약. MAPLE은 MoE 전문가 가지치기 방법이다. Gemma 4 26B-A4B의 전문가 128개 중 48개만 남긴다. 기준은 코드·논리 토큰의 활성 분포이다. 파일은 9.92 GB에서 4.75 GB로 줄었다. RTX 4050 6GB에서 45.4 tok/s이다. 자르지 않으면 PCIe를 거쳐 6.9 tok/s이다. 대상 밖 다국어 성능은 떨어진다. 스타는 31개이다. GitHub API는 라이선스를 표시하지 않는다. README 메타데이터는 Apache-2.0이다.

왜 중요한가. 작은 GPU에서 용도 특화 MoE를 돌리는 실험이다. 판정: 아직 이름. 평가는 저자 단위 테스트뿐이다.

반응. HN 20점·5개. 링크: 원문 · GGUF · HN 토론

7. LoreKit: 에이전트 메모리 공통 형식을 제안

출처. LoreKit 블로그

요약. 저자는 AGENTS.md, Anthropic 메모리 도구, Copilot Memory, MCP 메모리 서버가 서로를 읽지 못한다고 적었다. OpenTelemetry처럼 데이터 모델, 이름 규칙, 계약, 적합성 테스트를 합의하자고 제안한다. 기록마다 주소, 키, 작성자, 만료를 둔다. 작업은 write, read, list, search, archive이며 MCP로 노출한다. 저장, 순위, 임베딩은 표준 밖에 둔다. LoreKit 저장소는 스타 22개, MIT이다.

왜 중요한가. 여러 코딩 에이전트가 같은 저장소 기억을 공유하려면 공통 형식이 필요하다. 아직 제안 단계이다.
