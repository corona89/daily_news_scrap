3. AlphaProof Code: Signal 프로토콜 실제 코드를 Lean으로 형식 검증

출처. Google DeepMind 블로그 (11-10)

요약. AlphaProof Code는 여러 LLM을 쓰는 형식 검증 에이전트 프레임워크이다. 사람 전문가가 증명할 보안 성질을 정한다. Gemini Carbon 기반 에이전트가 증명한다. 에이전트는 Lean 코드 600만 줄 이상을 만들었다. 사람 검토가 필요한 부분은 코드의 1%였다. 설계가 아니라 컴파일된 실제 구현을 검증했다. 작업 기간은 4주이다. 이미 고친 실제 버그 2개를 다시 넣자 두 경우 모두 "안전하지 않음"을 증명했다. 검증 산출물은 오픈소스로 공개한다.

왜 중요한가. DeepMind는 널리 쓰는 암호 프로토콜 구현을 이 깊이로 검증한 첫 사례라고 말한다. AI로 보안 보증 비용을 크게 줄일 수 있다.

4. Amazon, 사내 티켓 분류에서 Sonnet 4.6을 Strands Decider로 바꿔 비용 98% 절감

출처. Strands Agents 블로그 (11-09, HN 11-10 15:01 KST)

요약. Amazon 엔지니어 2명이 티켓 20개 유형 분류에 쓰던 Claude Sonnet 4.6을 바꿨다. 새 모델은 결정 모델 Strands Decider의 Gemma 4 E4B판이다. 결정 모델은 글을 만들지 않고 선택지별 확률을 낸다. 호출당 시간은 4,215 ms에서 897 ms로 줄었다. 티켓당 토큰은 6,724개에서 2,010개로 줄었다. 티켓 100만 건 비용은 약 $22,200에서 약 $500이다. 모델은 A10G 24 GB 1장(ml.g5.xlarge)에서 약 19 GiB를 쓴다. 요청 1건은 약 640 ms이다. JSON 키 순서를 바꾸면 확률이 최대 0.19 바뀌었다.

왜 중요한가. 닫힌 선택지 분류는 대형 LLM 대신 작은 결정 모델로 바꿀 수 있다. 저자는 설명문이 필요하거나 분류 목록이 자주 바뀌면 맞지 않는다고 적었다.

5. MiniMax-H3-Image: 33.1B 오픈웨이트 이미지 생성·편집 모델, 16MP 직접 출력

출처. Hugging Face 모델 카드, The Reel Stack (11-10 공개)

요약. MiniMax는 MiniMax-H3-Image 가중치를 공개했다. 한 체크포인트로 텍스트→이미지와 이미지 편집을 한다. DiT는 33.1B 파라미터, 50층이다. 출력은 약 16MP이고 4096×4096부터 6272×2688까지이다. 업스케일러가 없다. 6단계로 증류했고 CFG를 쓰지 않는다. 참조 이미지는 최대 16장이다. BF16 DiT 파일은 66.28 GB이다. 텍스트 인코더 66.7 GB가 따로 필요하다. SGLang, vLLM-Omni, diffusers, ComfyUI를 지원한다. 라이선스는 MiniMax-H3-Image Community License이다. 이 라이선스는 미국, EU, 영국, 한국 사용을 별도 허가 없이 막는다. 벤치마크 수치는 모델 카드에 없음.

왜 중요한가. 고해상도 오픈 이미지 모델이다. 하지만 한국에서 직접 가중치를 쓰려면 MiniMax의 별도 허가가 필요하다. 판정: 지켜볼 만함(라이선스 제약).

7. e-means (Meta FAIR): k-means를 1/10 에포크로, 더 낮은 손실로

출처. 프로젝트 블로그, arXiv 2611.09501

요약. e-means는 Lloyd 알고리즘을 대체하는 k-means 방법이다. 미니배치와 지수 이동 평균으로 중심을 갱신한다. 배치 크기와 스텝 크기는 스케일링 법칙으로 자동으로 정한다. 하이퍼파라미터 조정이 필요 없다. Lloyd 25 에포크의 테스트 손실보다 낮은 값에 1.2–3 에포크로 도달한다. 실제 시간은 GPU에서 Flash-KMeans보다 10–45배 빠르다. CPU에서는 Faiss보다 8–15배 빠르다. 코드는 faiss/contrib/e_means에 있다. Faiss 라이선스는 MIT이다.

왜 중요한가. 벡터 검색 인덱스 학습과 데이터 정리에 바로 쓸 수 있다. 판정: 써볼 만함. 수치는 저자 측정이다.

반응. HN 492점·77개. Faiss 스타 41,340. 링크: 원문 · arXiv · HN 토론

8. Google TPU 8tx·TPU 8i Max: 기밀 추론용과 긴 문맥용 TPU 시스템 추가

출처. Google 블로그 (11-09)

요약. Google은 8세대 TPU 시스템 2개를 더했다. TPU 8tx는 기밀·보안 추론용이다. TPU 8t와 같은 칩이고 5세대 AMD EPYC 호스트를 쓴다. 사용 중 데이터와 가중치를 하드웨어에서 보호한다. 지연은 TPU 8t보다 최대 2배 낮다. TPU 8i Max는 TPU 8i 칩 2개를 한 패키지에 넣었다. 계산, SRAM, HBM 대역폭이 TPU 8i의 2배이다. 같은 랙 공간에 실리콘이 2배 들어간다. 가격과 출시일은 출처에 없음.

왜 중요한가. 에이전트용 긴 문맥 추론과 규제 산업용 기밀 추론을 따로 겨냥했다. TPU 고객은 거의 100곳이다.
