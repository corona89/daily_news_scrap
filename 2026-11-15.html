1. Claude Code Code Mode: Claude가 JavaScript로 도구를 묶어 호출하는 실험 기능

출처. Claude Code 변경 기록 v2.1.323 (11-12 미국 날짜), i10X·wmedia.es 독립 테스트. 이번 기간에 X에서 크게 퍼졌다.

요약. Code Mode는 기본으로 꺼져 있는 실험 기능이다. 켜면 Claude는 Bash, Read, Edit를 하나씩 부르지 않는다. Claude는 도구를 부르는 JavaScript를 쓰고, Claude Code가 그 코드를 세션 안에서 실행한다. 켜는 방법은 CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 환경 변수이다. Anthropic API와 대화형 터미널에서만 동작한다. 지원 모델은 Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.2이다. X에 퍼진 "37% 절감"은 2025년 11월 API 기능 Programmatic Tool Calling의 수치이다(43,588→27,297 토큰). Anthropic은 Code Mode 자체의 절감 수치를 내지 않았다. wmedia.es의 1회 테스트에서 전체 입력 토큰은 150,364에서 94,659로 줄었다. 같은 테스트에서 실행 시간은 15초에서 37초로 늘었다. 고정 도구 문맥은 24.6k에서 11.1k 토큰으로 줄었다.

왜 중요한가. 도구 정의 토큰은 매 요청에 붙는다. 이 기능은 그 고정 비용을 줄인다. 판정: 지켜볼 만함. 절감은 실제로 보이지만 느려질 수 있고, Remote Control과 Chrome 기능을 쓸 수 없다.

반응. HN 토론 없음. X 뉴스 요약에서 상위 AI 주제였다. 독립 테스트는 1회 측정이라 벤치마크가 아니다. 링크: 원문 · i10X 분석 · wmedia.es 테스트 · Anthropic 2025 원글

2. deepseek-v3-jax: DeepSeek V3 구조를 순수 JAX 190줄로 구현

출처. GitHub, Show HN (11-15 00:04 KST)

요약. 이 저장소는 DeepSeek-V3 기술 보고서의 핵심 구조를 JAX 190줄로 구현한다. MLA, decoupled RoPE, DeepSeekMoE, 보조 손실 없는 부하 균형, MTP를 포함한다. Flax와 PyTorch를 쓰지 않는다. 기본 설정 모델은 36.2M 파라미터이고 토큰당 13.6M을 쓴다. MacBook Air M5(24 GB)에서 약 2.6시간 동안 약 98M 토큰을 학습했다. 검증 손실은 5.02에서 3.51로 내려갔다. 균형 bias를 켜면 전문가 부하가 5.7–6.9%이고, 끄면 0.09–18.6%이다. 두 경우 2000 단계 검증 손실은 3.921과 3.923으로 같았다.

왜 중요한가. MoE와 MLA를 읽고 실험하기 좋은 교재 코드이다. 판정: 써볼 만함(학습용). 저자도 성능 모델이 아니라 구조 데모라고 말한다.

반응. HN 271점·27개. GitHub 스타 194개, 포크 17개, 마지막 푸시 11-15, MIT. 링크: 원문 · HN 토론 · 저자 해설 글

3. turbo-browser-mcp: 브라우저 MCP 도구를 10개 묶음 도구로 줄인 Playwright 서버

출처. GitHub, Show HN (11-15 13:09 KST)

요약. 이 MCP 서버는 25–33개의 세밀한 브라우저 도구를 10개 묶음 도구로 합친다. 바뀐 DOM만 돌려주는 delta 스냅샷, 한 번에 폼을 채우는 smart_fill_form, 디스크 경로로 파일 올리기를 제공한다. 자체 벤치마크에서 10필드 폼은 11턴에서 1턴으로 줄었다. 같은 작업의 토큰은 93.4% 줄었다. 클릭 후 delta 스냅샷은 전체 ARIA 3,582 토큰 대신 56 토큰이다. 도구 정의 토큰은 Playwright MCP보다 19.1% 적다. 제출 버튼 앞에서 멈추는 submit guard가 있다.

왜 중요한가. 브라우저 에이전트의 비용은 턴 수와 스냅샷 크기에서 나온다. 이 도구는 두 가지를 모두 줄인다. 판정: 지켜볼 만함. 수치는 모두 저자 자체 측정이고 저장소는 11-14에 생겼다.

반응. HN 46점·9개. GitHub 스타 106개, 포크 6개, 마지막 푸시 11-15, MIT, 버전 0.5.0. 링크: 원문 · HN 토론

8. Anthropic 블로그: Opus 5.5에서 작업 하나의 비용 계산법

출처. claude.dev 블로그 (11-09 게시, HN 11-15 10:57 KST)

요약. 글은 토큰 단가보다 턴 수와 캐시 적중률이 비용을 정한다고 말한다. Opus 5.5 가격은 입력 100만 토큰당 $4, 출력 $20, 캐시 읽기 $0.20이다. 입력과 출력은 Opus 5보다 20% 싸고, 캐시 읽기는 60% 싸다. 예시에서 2.8M 입력 토큰은 캐시 없이 $11.20, 캐시 90%에서 $1.62이다. 같은 토큰 수로 계산한 예시 세션은 Opus 5보다 약 31% 싸다. "40% 싸다"는 수치는 토큰 사용 감소를 더한 추정이라고 글이 밝힌다.

왜 중요한가. 에이전트 비용을 줄이려면 캐시를 깨지 않고 턴을 줄여야 한다. 계산기를 자기 작업에 넣어 볼 수 있다.

반응. HN 23점·20개. 링크: 원문 · HN 토론

9. Lovable 앱 보안 조사: 159,041개 프로젝트 중 다수가 로그인 없이 데이터 노출

출처. Crissy Field 연구 보고서 (HN 11-15 02:43 KST)

요약. 보안 회사 Crissy Field는 Common Crawl에서 Lovable 프로젝트 159,041개를 찾았다. 그중 34,545개가 Supabase를 썼다. 24,664개 사이트는 로그인 없이 페이지를 열자마자 DB 기록을 보냈다. 그중 7,403개(30%)에서 이메일이 든 표를 찾았다. 한 포럼은 프로필 80,000개 이상과 채팅 메시지 200,000건 이상을 노출했다. 한 업체는 여권 번호가 든 기록 1,000건 이상을 노출했다. 보고서는 30%를 확정 유출률로 읽지 말라고 말한다.

왜 중요한가. AI 앱 빌더로 만든 앱은 접근 제어(RLS)를 사람이 확인해야 한다. 노코드 에이전트 빌더를 만드는 팀에도 같은 위험이 있다.

반응. HN 970점·368개. 링크: 원문 · HN 토론
