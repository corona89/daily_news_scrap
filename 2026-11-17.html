1. SenseNova-Loop-9B: 반복(looped) 구조의 9B 멀티모달 모델

출처. Hugging Face 모델 카드 (SenseNova, 11-17 공개)

요약. 이 모델은 9B 파라미터이다. 32개 층 중 24개 층을 두 번 실행한다. 그래서 한 번의 순전파에서 56개 층을 계산한다. 문맥은 512K 토큰이다. 입력은 텍스트와 이미지이다. 라이선스는 Apache-2.0이다. 자체 표에서 AutomationBench는 36.67이다. Qwen3.8-27B도 36.67이다. AIDABench는 65.31이다(Qwen3.8-27B 65.01). NL2Repo는 41.36이다(Qwen3.8-27B 44.60). Preview 대비 Terminal-Bench 2.1은 40.45에서 59.55로 올랐다. GAIA는 37.86에서 69.90으로 올랐다. 4비트 가중치와 8비트 KV 캐시로 256K 문맥에서 약 15GiB GPU 메모리가 필요하다. 공식 AWQ 4비트 버전이 있다. API 가격은 출처에 없음.

왜 중요한가. 작은 파라미터로 깊은 계산을 하는 방법이다. 소비자용 GPU 한 장으로 로컬 에이전트를 돌릴 수 있다. 단, 층을 두 번 돌리므로 속도는 따로 확인해야 한다.

반응. HF 좋아요 169. HN 반응은 확인되지 않았다. 링크: 원문

2. Olala mini 7A1B: OVH의 첫 자체 LLM (Apache-2.0 예정)

출처. OVH 보도자료 (11-17)

요약. 총 7B 파라미터 MoE이다. 활성 파라미터는 1B이다. 층마다 전문가 256개가 있다. 주의 구조는 Differential-TPA와 Mamba-3를 섞었다. 8GB GPU에서 돌아간다. RTX A4500에서 초당 160토큰이다. GPU 없이 CPU에서 초당 50토큰이다. 문맥은 32,000 토큰이다. Hugging Face에 Apache 2.0으로 공개할 예정이다. 공식 출시는 11-19이다. 벤치마크 수치는 출처에 없음.

왜 중요한가. 유럽 기업이 공공 슈퍼컴퓨터로 처음부터 학습한 모델이다. Qwant가 이미 쓴다. 비용은 1/3로 줄고 응답은 20% 빨라졌다고 한다. 벤치마크가 나오기 전에는 성능을 판단할 수 없다.

반응. HN 반응은 확인되지 않았다. 링크: 원문

3. K2-Horizon 기술 보고서: 0.9B~375B 완전 공개 모델 6종

출처. Hugging Face Papers 2611.21003 (IFM/MBZUAI), AI Weekly 정리

요약. K2-Horizon은 0.9B 밀집 모델부터 375B-A23B MoE까지 6개 모델이다. LLM360 기준으로 중간 체크포인트, 사전학습 데이터, 학습 코드를 공개한다. 36B-A4B 모델은 MoVA(값 투영에 MoE 적용)를 쓴다. 이 모델은 같은 데이터의 32B 밀집 모델과 거의 같다. 활성 파라미터는 1/7이다. Uno 어댑터는 디코딩을 최대 2.2배 빠르게 한다. AI Weekly에 따르면 375B-A23B는 Toolathlon-Verified 65.3이다. SWE-Atlas-QnA는 48.4이다. HLE와 CritPt에서는 폐쇄 모델보다 약하다. 라이선스는 Apache-2.0이다(HF 태그). 작은 모델 가중치는 2026-09부터 HF에 있었다.

왜 중요한가. 데이터와 코드까지 공개한 큰 모델은 드물다. 규제 산업에서 학습 과정을 감사할 수 있다. 단, 375B와 36B는 데이터와 코드가 아직 없다고 한다.

반응. HF 업보트 70 (이날 2위). 링크: 원문 · AI Weekly · 36B-A4B 모델 카드

4. FrontierHarness Eval v1.1: 모델별 최적 코딩 하네스 비교

출처. Runta 블로그 (11-17), Baseten 협업

5. OpenCode Browse: 코딩 에이전트가 내 실제 브라우저를 쓰게 하는 MCP 서버

왜 중요한가. 별도 헤드리스 브라우저 없이 로그인된 세션을 쓴다. 편하지만 에이전트가 내 계정 권한을 그대로 가진다. 판정: 써볼 만함. 단, 허용 사이트를 좁게 설정해야 한다.

9. lend: 원격 코딩 에이전트에 자격 증명을 넘기지 않는 방법

출처. 개인 블로그 (11-13 작성, HN 11-17 게시)

요약. 저자는 에이전트를 버릴 수 있는 VM에서 돌린다. SSH 키, 1Password, gh CLI는 노트북에 둔다. lend는 원격 에이전트가 노트북의 도구를 쓰게 한다. 사용할 때마다 사용자가 승인한다. 비밀 값은 에이전트에게 보이지 않는다. 임대(lease)와 사용 기록도 있다.

왜 중요한가. 에이전트 보안의 실용적 패턴이다. 별 수와 라이선스는 이 글에서 확인하지 못했다. 판정: 지켜볼 만함.

반응. HN 126점, 댓글 110개. 링크: 원문 · HN

10. Claude Code 팀의 검증(verification) 방식

11. Windows 11이 코딩 에이전트 사용 기록을 수집한다는 분석

출처. Xusheng Li 블로그 (역공학 분석)

요약. 저자는 MissionControlAggregator.dll을 분석했다. 이 DLL은 codex.exe, claude.exe, copilot.exe, cursor.exe, antigravity.exe 등 이름을 비교한다. python.exe, node.exe, gcc.exe 같은 개발 도구도 확인한다. 기능 이름은 CLICodingAgentUsage(ID 62580080)이다. 선택 진단 데이터가 켜져 있으면 결과를 Microsoft로 보낸다. 이 설정은 기본으로 켜져 있다.

왜 중요한가. 회사 PC에서 어떤 AI 도구를 쓰는지 외부로 나갈 수 있다. 보안 정책이 있는 조직은 진단 데이터 설정을 확인해야 한다.

반응. HN 704점, 댓글 584개. 링크: 원문 · HN

13. 논문: SPILLWAY, SWE-CoWork, ScaleVLA

출처. Hugging Face Daily Papers (11-17)

요약. SPILLWAY는 도구 사용 에이전트의 프롬프트 주입 방어이다. 행동 대상이 도구의 타입 필드에서 왔는지 결정적으로 검사한다. 표준 주입 공격이 행동을 공격자에게 돌리지 못했다고 한다(HF 49). SWE-CoWork는 동료 26명이 있는 가상 조직에서 코딩 에이전트를 평가한다. 상위 두 모델은 테스트의 약 63%를 통과하지만 과제 완료는 8% 미만이다(HF 44). ScaleVLA는 552B DeepSeek-V4.1-Flash를 로봇 정책에 붙였다. LIBERO-PRO 성공률은 45.1%이다. 작은 백본은 최대 31.3%이다(HF 41).

왜 중요한가. 에이전트 보안과 실제 업무 평가가 핵심 주제이다. SWE-CoWork는 부분 구현과 완전한 납품 사이의 큰 차이를 보여 준다.

반응. HF 업보트 49 / 44 / 41. 링크: 원문 · SWE-CoWork · ScaleVLA
