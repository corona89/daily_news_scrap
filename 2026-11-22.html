1. LingSante-3.1-flash: Ant Group의 의료 특화 오픈 가중치 MoE 모델

출처. Hugging Face 모델 카드 (inclusionAI). X 뉴스 요약 (11-23 07:47 KST)

요약. LingSante-3.1-flash는 Ling-3.1-flash를 바탕으로 만든 의료 특화 모델이다. 구조는 하이브리드 선형 MoE이다. 총 파라미터는 560B이고 토큰당 활성 파라미터는 25B이다. 문맥은 1M 토큰이다. 라이선스는 MIT이다. 모델 카드는 벤치마크를 그림으로만 보여 준다. X 뉴스 요약에 따르면 HealthBench Professional 점수는 65.72이다. 같은 요약은 GPT-6 Astra와 Claude Opus 5.5보다 높다고 쓴다. 권장 서버는 H200 8장 또는 GB300 4장이다. MXFP4 변형은 11-22에 올라왔다. 가격은 출처에 없음. 카드는 의료 기기가 아니고 연구용이라고 밝힌다.

왜 중요한가. 의료 영역에서 큰 오픈 가중치 모델이 MIT 라이선스로 나왔다. 개인 PC에서는 돌릴 수 없다. 벤치마크 수치는 카드 본문 표가 아니라 뉴스 요약에서 나왔다.

반응. HF 좋아요 40개 (MXFP4 변형 7개). HN 출처에 없음. 링크: 원문 · MXFP4 변형

2. Sarvam-105B-1711: 도구 호출과 인도어를 강화한 105B MoE

출처. Hugging Face 모델 카드 (sarvamai). X 뉴스 요약 (11-22 공개)

요약. Sarvam-105B-1711은 Sarvam-105B와 같은 기본 모델을 다시 후학습한 것이다. 총 105B, 활성 10.3B인 MoE이다. 라이선스는 Apache 2.0이다. 카드 표의 BF16 점수는 다음과 같다. τ²-Bench는 85.5이다(Gemini 3.5 Flash-Lite 83.1, Gemma-4-31B 81.1). IFBench는 82.5이다(Gemini 3.5 Flash-Lite 73.5). GPQA Diamond는 80.4로 Gemma-4-31B(84.3)보다 낮다. LiveCodeBench v6는 75.3이다(Gemma-4-31B 81.9). 모든 점수는 Sarvam 자체 측정이다. B200 1장에서 사용자 1명일 때 사용자당 576 tok/s이다. 96GB RTX PRO 6000 1장에서도 NVFP4 빌드가 돈다(사용자 1명 61.8 tok/s). X 뉴스 요약에 따르면 API 가격은 100만 토큰당 $0.15이다. 문맥 최대 길이는 출처에 없음(시험 설정은 128k).

왜 중요한가. 지시 따르기와 도구 호출 점수가 같은 급 오픈 모델보다 높다. 수학·코딩·지식 점수는 Gemma-4-31B보다 낮다. 워크스테이션 GPU 1장에서 돌릴 수 있다.

반응. HF 좋아요 8개 (BF16 저장소 8개). HN 출처에 없음. 링크: 원문 · BF16 가중치

3. lookatmyquant: Inkling-2-Mini를 3.9~12.8GB로 줄인 양자화 컴파일러

출처. GitHub 저장소 README, Hacker News

요약. lookatmyquant는 양자화 컴파일러이다. 모델의 각 부분이 압축으로 출력을 얼마나 해치는지 잰다. 그다음 크기 예산 안에서 부분마다 다른 코드를 고른다. Inkling-2-Mini 텍스트 가중치 18.89GB를 Apple silicon용 MLX 빌드 6개로 줄였다. 12.76GB 빌드는 GSM8K 200문제 중 193개, HumanEval 164문제 중 152개를 풀었다. 이 수치는 BF16 원본과 같다. 8.87GB 빌드는 원본 점수의 99.2%를 유지했다. 이 빌드의 KL은 Unsloth 9.14GB UD-Q2_K_XL GGUF보다 2.34배 낮다. 5.38GB 빌드는 HumanEval이 71.3%로 떨어진다. 별 576개, MIT 라이선스, 마지막 푸시 11-23 06:48 KST이다. 평가: 써볼 만함. 32GB 미만 Mac에서 Inkling-2-Mini를 돌릴 수 있다.

왜 중요한가. 어제 공개된 Inkling-2-Mini를 작은 기기에서 돌릴 길을 연다. 8~13GB 빌드는 품질 손실이 거의 없다고 저자가 측정했다. 측정은 저자 자체 수치이다.

반응. HN 578점, 댓글 137개. 링크: 원문 · HN

4. Dragos 카나리 토큰 실험: AI 제공자 3곳 이상에서 프롬프트 데이터 노출

출처. Dragos 블로그, OpenRouter 블로그, Together AI 보안 공지

요약. Dragos는 7월부터 11월까지 AI 서비스에 프롬프트 약 200만 개를 보냈다. 각 프롬프트에는 추적용 URL과 가짜 AWS 자격 증명을 넣었다. 최소 3개 제공자의 데이터가 노출된 흔적을 찾았다. 추론 마켓플레이스의 일부 재판매자는 일반 로그 기능으로 고객 프롬프트를 보고 보관했다. 미국 제공자에게 보낸 프롬프트가 중국 AI 조직으로 간 사례도 있었다. OpenRouter는 제공자 3곳을 내보냈다. 또 엔드포인트 125개를 Zero Data Retention(ZDR) 대상에서 뺐다. Together AI는 AI 코딩 에이전트가 자격 증명을 공개 저장소에 커밋했다고 밝혔다. 그 자격 증명으로 제3자가 6~7월 프롬프트 샘플을 내려받았다. Together는 새 계정의 기본값을 ZDR로 바꿨다.

왜 중요한가. 오픈 모델을 외부 추론 제공자로 쓰면 프롬프트가 새어 나갈 수 있다. ZDR 표시만으로는 보장이 안 된다. 코딩 에이전트의 자격 증명 커밋도 실제 사고 원인이 되었다.

반응. OpenRouter 글 HN 277점, 댓글 92개. Dragos 글 HN 97점, 댓글 22개. Together 글 HN 47점, 댓글 11개. 링크: 원문 · OpenRouter 공지 · Together 공지 · HN(OpenRouter) · HN(Dragos) · HN(Together)
