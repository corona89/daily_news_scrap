1. GLM-5.4: Z.ai의 첫 루프 트랜스포머 플래그십 모델

출처. Z.ai 공식 블로그 (11-23). Hacker News

요약. GLM-5.4는 GLM-5 기본 모델의 28개 층을 2번 반복해서 실행한다. 규모는 750B이다. 문맥은 1M 토큰이다. Z.ai는 2T~3T 파라미터 모델과 비슷한 지능이라고 주장한다. 같은 구조의 30B 모델 비교에서 학습 연산을 약 10% 더 쓰고 수학·과학·긴 문맥 점수가 올랐다고 쓴다. GPQA-Diamond와 MMLU-Pro에서 평균 출력 길이는 10–14% 줄었다. 속도는 한가한 시간에 최대 200 tok/s, 혼잡한 시간에 70–80 tok/s이다. 블로그의 벤치마크 결과는 그림으로만 있다. 그래서 경쟁 모델과 비교한 숫자는 출처 본문에 없음. 지금은 GLM Coding Plan에서 쓸 수 있다. API는 곧 나온다. 가중치는 안전 작업 뒤에 공개할 계획이다. 가격은 출처에 없음. 주간 할당량은 GLM-5.3보다 50% 많다.

왜 중요한가. 큰 상용 모델이 루프(가중치 공유 반복) 구조를 처음으로 쓴 사례이다. 회사는 긴 "마라톤 사고"가 약점이라고 스스로 밝혔다. 가중치가 나오기 전에는 로컬 실행을 할 수 없다.

반응. HN 1,000점 / 댓글 328개. 별도 HN 글 58점 / 11개. 발표 X 글 좋아요 8,910개, 조회 약 110만. 링크: 원문 · HN · X 발표

2. Ling-3.2-air: inclusionAI의 124B 멀티모달 MoE (MIT)

출처. Hugging Face 모델 카드 (inclusionAI, 11-23 12:55 KST 생성)

요약. Ling-3.2-air는 하이브리드 선형 MoE이다. 총 124B이고 활성 파라미터는 5.5B이다. 구조는 Ling-3.0-flash-VL과 같은 네이티브 멀티모달이다. 라이선스는 MIT이다. 카드는 이전 모델과 비교한다. AutomationBench-AA는 15.7%에서 61%로 올랐다. AA-Briefcase v1.1 Elo는 987에서 1340으로 올랐다. Terminal-Bench 4.0은 0%에서 27%로 올랐다. Artificial Analysis Intelligence Index v5.0.1 점수는 23이다. 다른 회사 모델과 비교한 숫자는 출처에 없음. 권장 실행 환경은 256K 문맥에서 141GB급 GPU 4장이다. 가격은 출처에 없음.

왜 중요한가. 활성 5.5B라서 같은 크기 모델보다 추론 비용이 낮다. 다만 총 124B이므로 일반 PC에서는 돌리기 어렵다. 업무 자동화와 문서 작업에 초점을 맞춘 오픈 가중치 모델이다.

반응. HF 좋아요 97개. HN 출처에 없음. 링크: 원문

3. NariQ: Qwen3.8-27B를 10GB 파일로 줄여도 BF16 수준

출처. Hugging Face 모델 카드 (nari-labs). Hacker News

요약. NariQ는 트렐리스 부호화 방식의 사후 양자화이다. 실제 코딩 에이전트 기록으로 보정했다. 3비트 파일은 10.1GB이다. BF16 원본은 53.8GB이다. DeepSWE v1.1에서 3비트는 41.0%, BF16은 39.8%이다. Terminal-Bench 2.1에서 3비트는 63.8%, BF16은 62.6%이다. 2비트(6.8GB)는 DeepSWE 28.6%로 크게 떨어진다. 24GB GPU에서 3비트는 약 135K 문맥이 들어간다. 전용 llama.cpp 포크가 필요하다. 라이선스는 Apache 2.0이다.

왜 중요한가. 24GB GPU 1장으로 27B 코딩 에이전트 모델을 거의 손실 없이 쓸 수 있다. 수치는 Nari Labs 자체 측정이다. 평가: 써볼 만함. 단, 포크 의존이 단점이다.

4. OpenAI "Perplexity and Intelligence": 퍼플렉서티를 공통 안전 지표로

출처. OpenAI 블로그 (Jakub Pachocki, 11-22 미국 시간). Hacker News

요약. OpenAI 수석 과학자가 내부 log-perplexity 수치를 처음 공개했다. GPT-3.5는 약 0.99이다. GPT-4는 약 0.91이다. 현재 모델은 0.8 아래이다. 약 0.76 모델부터 수학 미해결 문제에서 큰 결과가 나왔다고 쓴다. 다음 구간인 0.68–0.7에서 새 능력이 나올 것으로 예상한다. 글은 업계가 이 지표로 공동 개발 한도를 정하자고 제안한다. 글은 한계도 밝힌다. 연구소마다 평가 데이터가 다르다. 사고 사슬(CoT) 효과는 이 지표에 나타나지 않는다.

왜 중요한가. 프론티어 연구소가 사전학습 진척 수치를 공개한 드문 사례이다. 안전 규제 논의에서 기준 지표가 될 수 있다.

6. LocalCode: Mac에서 로컬 모델로 돌리는 에이전트 코딩 도구

출처. GitHub 저장소. Hacker News

요약. LocalCode는 한 명령으로 Mac에서 코딩 에이전트를 실행한다. 파일 편집, 테스트, Git, 셸 명령을 프로젝트 안에서 처리한다. 프로젝트 밖을 건드릴 때는 먼저 묻는다. 모델 12종과 양자화 선택지 169개를 고른다. 목록에는 Qwen 3.8 27B, Inkling 2 Mini, DeepSeek V4 Flash가 있다. 요구 사항은 Apple Silicon과 메모리 16GB 이상이다. OpenAI 호환 API도 제공한다.

왜 중요한가. 로컬 모델 선택, 다운로드, 실행을 한 도구로 묶었다. 클라우드 비용 없이 코딩 에이전트를 쓰려는 Mac 사용자에게 맞다. 평가: 써볼 만함. 별은 아직 적지만 커밋 879개로 활발하다.

반응. HN 70점 / 댓글 21개. GitHub 별 149개, 최신 릴리스 v0.5.43 (11-23 00:43 KST), 라이선스 Apache-2.0. 링크: 원문 · HN
