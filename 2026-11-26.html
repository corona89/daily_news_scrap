1. GigaChat 4: Sber의 708B-A41B·37B-A4B 오픈 가중치 MoE 모델

출처. Hugging Face 모델 카드 (ai-sage). GitHub salute-developers/gigachat4. 11-26 AI Journey 발표

요약. GigaChat 4는 MoE 모델 2종이다. 708B 모델은 활성 파라미터가 41B이고 MIT 라이선스이다. 37B 모델은 활성 4B이고 개인 비상업 라이선스이다. 문맥 길이는 1,048,576 토큰이다. Gated DeltaNet과 DeepSeek Sparse Attention을 3:1로 섞는다. 한 모델에서 즉답 모드와 추론 모드를 요청마다 고른다. 708B 추론 모드의 SWE-bench Verified는 80.89이다. 같은 표에서 DeepSeek V4 Flash는 81.80, GLM-5.3은 86.67이다. GPQA Diamond는 82.83이다(DeepSeek V4 Flash 91.00). 37B의 LiveCodeBench v6는 85.00이다(Qwen3.6-35B-A3B 65.00). 37B의 SWE-bench Verified는 70.80이다(Qwen3.6-35B-A3B 67.80). 37B FP8은 H100 80GB 1장에서 돈다. 708B FP8은 H100 8장 노드 2대가 필요하다. GGUF도 있다. API 가격은 출처에 없음.

왜 중요한가. 러시아 연구소가 1M 문맥의 대형 MoE를 MIT로 풀었다. 37B는 GPU 1장에서 돌지만 상업 이용은 안 된다. 수치는 Sber 자체 측정이다.

반응. HF 좋아요 708B 44, 37B 30. GitHub 별 16. HN 반응은 기간 안에 없음. 링크: 원문 · 37B · GitHub

2. GRH Lean 증명의 훨씬 짧은 판 (Anthropic)

출처. GitHub lsernau/grh-lean (11-25 미국 시간). Hacker News

요약. 리만 가설과 디리클레 L-함수의 일반화 리만 가설(GRH)을 Lean 4로 증명한 저장소이다. Levent Alpöge의 증명을 바탕으로 Anthropic 동료들과 Claude가 줄였다. 읽기용 판은 약 300,000줄이다. 압축판은 같은 정리 5개를 약 76,000줄로 담는다. 이전 Alpöge 증명은 1,700만 줄이었다. 빌드는 12코어, 24GB 메모리에서 1~2시간 걸린다. 기계 검사만 통과했고 수학자가 끝까지 읽지는 않았다. 라이선스는 Apache-2.0이다.

왜 중요한가. AI가 만든 형식 증명을 사람이 읽을 수 있는 크기로 줄이는 일이 시작되었다. 증명 검토 비용이 크게 줄 수 있다.

반응. HN 543점 / 댓글 344. GitHub 별 867. 링크: 원문 · HN

3. "지연 시간은 거짓말하지 않는다": Jev는 아마 Qwen3.5-35B-A3B

출처. Modaic 블로그 (11-24 게시). Hacker News

요약. Modaic은 TypeSafe의 판단 전용 모델 Jev의 기반 모델을 추정했다. 서로 다른 프롬프트 9,984개로 지연 시간을 쟀다. Jev가 보고하는 토큰 수보다 Qwen 토크나이저 수가 지연 시간과 더 잘 맞았다. 프리필 처리량은 Qwen3.5-35B-A3B 기반 모델과 가장 비슷했다. 그 차이는 3.2K 토큰에서 22%, 8.8K 토큰에서 7%였다. 밀집 27B 모델은 초당 약 35K 토큰에서 멈췄고, Jev는 90K 넘게 올랐다. 자기 정체성 질문 22종에서도 Qwen 쪽 답이 많았다.

왜 중요한가. API 뒤의 모델도 지연 시간과 토크나이저로 기반 모델을 추정할 수 있다. 저자는 근사 지문이라고 한계를 밝힌다.

반응. HN 337점 / 댓글 94. 링크: 원문 · HN

4. Anthropic, Messages API를 Python에서 Rust로 이전

출처. Anthropic 엔지니어링 글 (2026-11-25)

요약. Anthropic은 Messages API를 Python에서 Rust로 옮겼다. 2024년 초부터 2026년 가을까지 API 트래픽은 약 1,800배 늘었다. Claude가 핵심 요청 경로 첫 판을 약 1주일에 썼다. 4월에 Rust 판은 테스트의 약 98%를 통과했지만, 실제 트래픽에서는 약 4분의 1만 일치했다. 팀은 운영 API를 검증기로 썼다. 차이를 찾으면 에이전트가 자동으로 고쳤다. 결과로 요청당 CPU는 약 70% 줄었다. 첫 토큰 시간 중앙값은 약 20% 줄었다.

왜 중요한가. 테스트만으로 검증이 어려운 운영 시스템 이전에서 에이전트를 쓰는 방법을 보여 준다. 핵심은 운영 트래픽을 비교 기준으로 쓰는 것이다.

반응. HN 31점 / 댓글 10. 링크: 원문 · HN

5. Bare Metal Qwen: 24KB 어셈블리 OS에서 Qwen3-0.6B 실행

출처. GitHub alesha-pro/llm.asm. Hacker News

요약. 순수 x86-64 NASM 어셈블리로 만든 부팅 가능한 OS이다. Linux, C, libc 없이 Qwen3-0.6B를 돌린다. 커널 크기는 24,252바이트이다. 콜드 부팅에서 채팅까지 74~94ms 걸린다. QEMU KVM(AMD EPYC 7642, vCPU 16개)에서 초당 134.9 토큰을 낸다. AVX2, FMA, F16C가 있는 CPU가 필요하다. GitHub 별 1,455, MIT, 마지막 커밋 2026-11-26이다. 판정: 지켜볼 만함. 학습·연구용으로 좋지만 실무 추론 엔진은 아니다.

왜 중요한가. 추론 엔진의 최소 구성을 보여 준다. 작은 모델은 운영체제 없이도 돈다.

8. Mixture-of-Loops Transformer (MoLT)

출처. arXiv. Hugging Face Daily Papers 11-26

요약. MoLT는 루프 트랜스포머에서 KV를 루프 사이 메모리로 다시 쓴다. U-MoLT는 4,000억 토큰 사전학습에서 OLMo3보다 좋았다. 700M 모델에서 검증 CE 토큰 효율이 1.7배였다. 3B MoE에서 10개 도메인 perplexity가 0.75 좋아졌고, 10개 과제 정확도가 2.1%p 올랐다. 코드 저장소 별은 69이다. 라이선스는 출처에 없음.

왜 중요한가. 같은 파라미터로 더 깊게 계산하는 방법이다. 작은 모델의 학습 효율을 높일 수 있다.
